# Changelog

Notable changes to Deck. The npm package (`@echodial/deck`) and the Composer package (`echodial/deck`) share version numbers; Composer reads the version from the git tag.

## 0.1.4 (unreleased)

### Fixed

- **Modals open centred.** `.modal` now sets `margin: auto`. The reset's `* { margin: 0 }` removed the browser's own centring of modal dialogs, so every `.modal` opened with `showModal()` sat in the top-left corner of the window.
- **Icons in running text stay on the line.** `.icon` is now `display: inline-block`. The reset's `svg { display: block }` put an icon inside a sentence on a line of its own, despite `.icon`'s baseline alignment. Icons in flex and grid rows (buttons, alerts, tiles, fields) are laid out exactly as before, because flex and grid items are blocks either way.
- **Long modals keep their footer.** An open `.modal` is now a flex column, and so is a `<form method="dialog">` wrapped around its regions. `.modal` caps its height at `min(85dvh, 48rem)` and clips, and `.modal-body` was meant to scroll, but an open modal was laid out as a block, so the body never shrank: in a window shorter than the dialog, everything past the cap was clipped, the footer and its buttons included. Now the body scrolls while the header and footer keep their height. `flex-direction: column` is on `.modal` itself rather than on `.modal[open]`, so the regions stay stacked while a closing modal fades out.
- **Dark mode no longer has light blocks in it.** `.progress`, `.ring`, `.spinner`, `.skeleton`, `.range` and `.range-pair` drew their tracks with `--ink-100` and `--ink-200`, and the status badges, alerts and `.banner-warn` filled with `--good-100`, `--warn-100` and `--bad-100`. All of these are fixed light values, so each drew a near-white shape on a dark page, and a `.btn-ghost` inside `.alert-good`, `.alert-warn` or `.alert-bad` was all but invisible (1.03:1). They now use theme-aware tokens. Light mode is unchanged, pixel for pixel.
- **The combobox placeholder is escaped.** `data-placeholder` was written into the combobox's markup unescaped, so a placeholder containing a double quote could add attributes to the input, an `onfocus` handler included, and an ordinary placeholder with a quote in it was cut short. It is now escaped like every other string the combobox renders. The markup and data attributes are unchanged.
- **`.banner-close` clears the 44px touch target.** It was only as big as its icon, 25×22px. It is now a `--tap` square with the icon at its old size, and it reaches into the banner's padding rather than making the strip taller. A `.btn.banner-close` is unchanged, because `.btn` already had a 44px target.
- **The combobox list opens next to its field.** Where the browser has anchor positioning, the list covered the field it belonged to on every page, because `position-area` was measured inside `.combo`, which is only as tall as the control. On a phone inside a `.card`, the list was laid out against the card rather than the screen, since the card's `contain: layout` captures even `position: fixed`, and the card's `overflow: clip` then cut it off. deck.js now opens the list as a popover in the top layer, so no ancestor can clip it, and places it with anchor positioning, the Floating UI adapter, or its own placement, in that order. On a phone it stays anchored to the field, with 44px rows, instead of becoming a sheet across the bottom of the screen.
- **Remote comboboxes keep earlier choices, and post them.** With `data-url` and `data-multi`, a choice made under one query was dropped by the next unless the new results happened to contain it, and no remote choice ever reached the `<select>`, so the form posted none of them. The selection is now kept apart from the results, every chosen value is written into the `<select>`, a token can be removed whatever the current results are, and a slow reply to an old query no longer replaces a newer one's results.
- **Long comboboxes open at once.** Only the options near the scroll position are drawn, so 10,000 options open in about 16ms instead of 1.4s (Edge). The arrow keys still reach every option and wrap at the ends, `PageUp` and `PageDown` move a screenful, and the active option is announced through `aria-activedescendant` with its place in the whole list. The docs had always said `aria-activedescendant` was set; it was not. `ArrowUp` with nothing active now goes to the last option rather than the second-to-last.
- **Focus rings inside lists and scrollers are whole.** `.list` clips, so a focused `.list-row` lost the sides of its ring, plus the top on the first row and the bottom on the last. The ring is now drawn inside the row, and follows the list's rounded corners. `.scroller` clipped the top of every focused item's ring and faded the ring of an item at the end edge. It now has 4px of top padding, so content below a scroller moves down 4px. Its fade lifts while keyboard focus is inside.
- **Scrolled cards rest at the gutter.** `.scroller` has `scroll-padding-inline` equal to its own inline padding. Before, the first card snapped flush against the screen edge on load, and so did any card scrolled into view. A scroller you have made flush with `padding-inline: 0` needs `scroll-padding-inline: 0` as well.
- **`.card-link` responds to keyboard focus.** Tabbing to the stretched link, or to anything else in the card, gives the card the same lift as hover.
- **`.nav-link` keeps one height with or without an icon.** It is now `inline-flex` with centred items, so an icon no longer sits on the text baseline, where its size and the font could make the link taller. Text-only links are the same size as before.
- **A `.btn` label split at a bare `<span>` reads as one phrase.** `Save <span>changes</span>` used to put the 8px gap between the words. A span with no class and no child elements now joins the label's text. A span with a class, such as a badge or `.sr-only`, keeps its box and the gap.
- **`.form-actions-sticky` sits above `.tabbar`.** It used to slide underneath the tab bar. `body:has(.tabbar)` now publishes its clearance as `--tabbar-clearance`, the sticky bar uses it, and the bar drops its own safe-area padding while the tab bar is showing.
- **`aria-pressed` and `aria-selected` both mean "on".** `.chip`, `.reaction` and `.datepicker-preset` used to respond only to `aria-pressed="true"`, and `.segmented` only to `aria-selected="true"`, so the wrong one showed no state and raised no error. All four now accept both, with the same look as before. deck.js moves either attribute when a `.segmented` is clicked, and no longer selects an `aria-selected` table row that contains one.
- **Small pointing icons mirror under `dir="rtl"`.** The automatic mirror in `src/19-logical.css` matched `#chevron-right` but not `#chevron-right-sm`, so an `.icon-sm` arrow or chevron kept pointing the wrong way in a right-to-left page. Every pointing icon is now listed with its `-sm` cut.
- **`.g-scrim` darkens an `<img>` child.** The scrim painted under every child, so with the photo as an `<img>`, rather than as the element's background, the caption sat on the bare image. An `img`, `picture`, `video`, `canvas`, `svg`, `iframe`, `.lazy` or `.video` child now sits under the scrim; other children still sit above it.
- **A failed `.lazy` image shows that it failed.** deck-extras.js set `.is-error` on the frame and nothing styled it, so the shimmer ran forever. The shimmer now stops and a broken-image glyph appears in the frame. The script also catches an image whose markup `src` failed before the script loaded, which fired no event.
- **`.grid-fixed-2`, `-3` and `-4` work without `.grid`.** They set only the columns, so on their own they did nothing. Each now sets `display: grid` and the gap itself; `grid grid-fixed-3` is unchanged, and print unwinds them like `.grid`.
- **`.split-rail-start` is described correctly.** It sizes the first track as the rail, so the rail goes first in the markup. Its comment and the split docs said the opposite, and the docs example showed the main column squeezed into the rail's width.
- **`.file` takes a dropped file.** It looked like a drop zone and ignored drops. With deck-extras.js, dragging a file over it sets `.is-over` (a solid border and the focus ring), and a dropped file goes into the input as a pick would: filtered by `accept`, one file unless `multiple`, then `input` and `change`. A drop the page's own handler has already taken is left alone.
- **SortableJS can load after Deck.** With Deck deferred, a SortableJS deferred after it or loaded `async` was not there when the adapters first ran, and the list was left on the native fallback for good, so drag handles did not work on first load. A list on the fallback is now handed to SortableJS when it arrives (at `DOMContentLoaded` or `load`, or on any later `Deck.init()`). The native fallback now honours `data-handle`.
- **Small icons from Deck's helpers use the small cut.** `Deck::icon($name, 'icon icon-sm')` and the icons deck.js renders with `.icon-sm` (date picker, combobox, toasts) pointed at the regular `#name` symbol rather than the heavier `#name-sm` drawn for 16px.
- **`.video-poster` shows its play button.** The poster image and the button were two grid rows, so the image overflowed the frame and the button sat below it, clipped. The image now fills the frame and the button is centred on it.
- **An exact brand colour reaches `.btn-primary`.** The documented override, `--brand` and `--brand-hover` on `:root`, recoloured links and outline buttons but not primary buttons, which filled with the `--brand-600` and `--brand-700` ramp steps. They now fill with `--brand` and `--brand-hover`. Light mode looks exactly as before. In dark mode a primary button is now the lighter step a link uses, with black text worked out from the fill, where it used to be the 600 step with white text in both schemes.

### Added

- **Read, set and clear a combobox from script.** `el._deck.value()` returns the selection (a string, or an array with `data-multi`), `el._deck.value(v)` replaces it with a value, an array, or `{ value, label }` objects, and `el._deck.clear()` empties it. Both keep the `<select>` in step and fire `change` and `deck:change` as a pick does; `{ silent: true }` skips the events.
- **Toggle buttons.** A `.btn` with `aria-pressed="true"` now has a visible on state: the brand tint with a brand edge. A pressed `.btn-soft` fills solid, and the solid variants go a shade darker. `aria-pressed` is now Deck's attribute for "on"; the table at `docs/components/button.php#on-attribute` lists what each component accepts. Pages that already put `aria-pressed` on a `.btn` with their own pressed styles will see Deck's on state wherever their rules leave a property unset.
- Seven theme-aware tokens. `--surface-recessed` is the recessed surface a control sits on: a progress, range or ring track, or a skeleton's sweep. `--good-soft`, `--warn-soft` and `--bad-soft`, each with a `-text` partner, are the status equivalents of `--brand-soft` and `--brand-soft-text`. Reach for these rather than the `--ink-*` and status ramps, which are the same colour in both themes.
- Layout regression tests that render the built stylesheet in a real browser: `npm test`. They use Microsoft Edge by default; set `DECK_TEST_BROWSER` to `chrome` or to the path of a Chromium executable to use another. `playwright-core` is a dev dependency only; Deck still ships no runtime dependencies.
- **Ten icons.** `inbox` and `arrow-down-right`, plus a media set: `play`, `pause`, `skip`, `fullscreen`, `tv`, `film`, `music` and `broadcast`, each in both cuts. The sprite is 86 icons, 174 symbols. `docs/components/icon.php#set` lists every icon in it.
- **Layout utilities.** `.ratio-2x3` for posters and book covers, `.object-contain` to letterbox instead of crop (it beats a `.ratio-*` frame's cover), `.break-words` (`overflow-wrap: anywhere`, which also stops a long string widening a flex item or table cell), and `.z-sticky`, `.z-nav` and `.z-sheet`, which put your own chrome on Deck's named stacking layers.
- **`.input-sm` and `.input-lg`,** the heights of `.btn-sm` (34px) and `.btn-lg` (50px). They work on `.select` and inside `.search` too. Every control is still 16px on a touch screen.
- **`.list-flush`,** a list with no border, radius or fill of its own, for a list inside a card or a sheet.
- **Dismissible alerts.** A `<button class="alert-close">` last in an `.alert` closes it: a 44px target that does not make the alert taller. deck.js hides the alert after a cancellable `deck:dismiss` event, and works for alerts inserted after the page loaded.
- **`.grid-fill`,** the auto-fit grid with `auto-fill`, so a short last row keeps card-sized columns instead of stretching. It needs no `.grid` beside it.
- **`.glass`,** a frosted, theme-aware surface for a card, panel or bar over an image. `--glass` sets the opacity (76%). Opaque under `prefers-reduced-transparency`.
- **`.g-scrim-auto` and `--scrim-auto`,** a scrim in the theme's surface colour with `--text` over it, so text over an image follows a light theme. `--scrim` stays dark, for white text.
- **`Deck::head()`, `Deck::css()` and `Deck::js()` take a CSP nonce.** `Deck::head(nonce: $nonce)` puts it on the stylesheet link, every script tag and the hue `<style>`, so the helper works under a strict Content Security Policy.

### Changed

- `src/deck-icons.svg` gained `menu-book` and `menu-book-sm` after 0.1.3. The brand artwork, which uses only the `deck-mark` symbol, did not change; `src/brand/sources.json` records the sprite's new hash so the build accepts it. `menu-book` is now listed in `tools/icons/icons.txt` as well, so regenerating the sprite keeps it.
- `Deck::head()` no longer prints an inline `<script>` to set the sprite URL. `Deck::js()` puts it on the first script tag as `data-deck-icons`, which deck.js already read; the result is the same.

Releases before 0.1.4 are described in the git history.
